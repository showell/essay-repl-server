# 2026-11-02: the day the chat got a design

## Where the day started

The morning was cleanup on roc-chat:
- deleting dead fields from stored records;
- a migration script, run on prod;
- a rename pass that swept "codec" out of the vocabulary.

Each pass took something away, and each one exposed the next layer. Then a cold read of one module, `Messages.roc`, asked the right question: what is this module *about*? The honest answer was "whatever its callers needed". The code worked: humans and agents really did talk through it, and that proved the concept. What it lacked was nouns.

So we started over. Restarting is cheap when the expensive parts carry forward:
- **what it learned:** the product knowledge, and a working chat that showed agents and humans can share one;
- **its file format:** the transcript format;
- **its renderer:** roc-markdown;
- **its JS:** the client code, which we can still crib;
- **its record:** a long list of things not to do again.

## Listening mode

The best hour of the day was a conversation, not code. The rule was that you answer, and I ask only the single most fundamental next question. It went:
- who the chat is for;
- what a message is;
- what an author is;
- whether a conversation stands alone;
- what a channel is, and what a DM is.

Each answer settled some things and set others aside:
- **The nouns:** a message is an author, a time, markdown, and the id its conversation gives it. Messages are immutable, and an edit is a new message. A conversation stands alone.
- **Removed:**
  - *mentions*, because agents are smart enough to read everything;
  - *paging*, because conversations die off naturally;
  - *stream resume*, because a reload is fine.
- **On disk:** the Zig chat's transcript format, readable with `cat`, with no codec in sight.

Much of what we'd spent weeks building in roc-chat turned out to be unnecessary, and the design doc came out of the questions in under an hour.

## A Roc core that shows off Roc

Then 264 lines of Roc rendered a fake three-way conversation between you, LC and CC. Your first reaction set the tone for everything after: *that shows off Roc*.

The rest of the day pushed that idea further:
- **`Message.Id`** is a U16 with no constructor but `first` and `next`.
- **A `Conversation`** grows only by `append`, so ids can't skip, and times can't go backwards (`Backdated`). The clocks went back a day earlier, which made that last rule feel timely.
- **`TrustedHtml`** shrank to one scary door, `dangerously_trust`, used in six places a reviewer can list.
- **`SecureImageTag`**, **`UnvalidatedString`** and **`SignedIn`** are the trust boundaries, named so a security inspector finds them first. Their headers point at each other, so a reader who starts at one walks the whole trail.
- **`Name`** is an allowlist of letters, and `Élodie` gets the file stem `elodie-5`.
- **`Human`** is a type, so a DM with an agent in it can't even be written.
- **`MsgAnchor`** and **`UserPair`** are tiny modules that exist only so a rule has one home.

None of these is clever. Each one moves a promise from a comment into a type, where the compiler keeps it for us.

## Reviews by cold agents

The process grew in layers. Here are the layers in order:
1. **Implementers:** an agent writes a round of code.
2. **The gate:** `tools/verify.shale` runs in about two seconds. Every `expect` in the source must pass exactly once, every spec must be wired in, the shale style hunts are held at zero, and the demo page must match its frozen copy byte for byte.
3. **Cold reviewers in parallel, each with its own lens:** cohesion, type design, tests, security, flow of control.
4. **More imaginative reviews:**
   - a nitpicker that names exactly ten renames with no justification;
   - a second agent that turns those renames into principles;
   - from those principles, a new shale hunt (`taken_word`) and five new rules in the style guide.

The reviewers found real things:
- a reachable crash in roc-chat;
- a transcript reader that accepted a file the writer could never produce;
- a gate check that could never fail;
- a build that didn't watch its markdown dependency;
- two dependencies pointing the wrong way.

Each finding became a fix, and most fixes became a type. Several times a reviewer said NOT YET and was right. The sign-off, when it came, meant something.

Your own pushes shaped it as much as any reviewer:
- smaller modules ("easier to combine than split");
- fail loudly, and make scary things obviously scary;
- `DateTime` rather than `Timestamp`;
- don't call part of a transcript a transcript;
- graphviz pictures, because a design smell is easier to see in a picture.

## Where it stands

About 4,700 lines of Roc, almost all of it pure, with tests at the bottom of each module that read like a spec. The first milestone, 2,000+ lines signed off by design, security and test reviewers, came and went.

Users, Channels and DMs are in: one namespace, admins proven by type, and DMs that start with their first message.

As I write, an implementer is building the first server:
- **Zig:** plain HTTP with no routing, plus chat-agnostic file primitives with long, exact names, such as `append_utf8_bytes_to_file` and `replace_file_with_utf8_bytes_atomically`.
- **Roc:** a `FileSystem` module whose functions are about four lines each, with `Utf8TranscriptMessage` in and `Utf8Transcript` out.

You predicted something that feels like chat around 1,500 lines. The core is well past that. The server is the step that will make it feel like chat.

Today, roc-chat stopped being where new work goes, and a better chat started.

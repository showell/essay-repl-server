# roc-chat as a standalone, forkable repo: what it depends on, and how to keep it from drifting

*A cold agent's read-only evaluation for Steve, 2026-10-28, lightly edited by the box. No repo was changed. The only builds were stock-Zig test runs, with their caches in a scratch folder. Checkouts read:*
- *roc-webbox `main` e0ce512;*
- *zig-webbox `master` ac6bb97;*
- *angry-gopher `box/roc-cleanup` 056cb41a;*
- *zig-metal-unikernel `master` (v41).*

## The short answer

- **The Zig layer a Linux chat needs is all of zig-webbox, plus the chat's own host, which lives in angry-gopher today.**
  - The chat reaches site, http, bus, sse, store, edge, signed_cookie, site_secret, counter, mem_meter, html and client_address, plus `webbox_linux` to serve.
  - A vendored "subset" would be almost all of webbox's ~9,400 non-test lines, so trimming it gains nothing.
- **zig-webbox is a clean package.** It has no dependencies, its repo is public, and it carries a fingerprint. `zig fetch git+https://github.com/showell/zig-webbox#ac6bb97…` worked with stock 0.17.0.
- **Recommendation: options 4 and 2 together.**
  - roc-chat becomes the chat's one home: the Roc, its platform, the seam, the chat's Zig host (moved out of angry-gopher), the JS client, and a small Linux main with its own minimal login.
  - roc-chat pins zig-webbox by URL and hash in `build.zig.zon`, so there is no second copy of webbox to drift.
  - angry-gopher, and through it `gopher.elf`, consumes roc-chat by path.
  - Webbox version skew (not copy drift) is caught by adding roc-chat to zig-webbox's `consumers` step, built against the live tree.
- **A forker needs stock Zig 0.17.0 and the pinned Roc nightly, and nothing else.** No patched Zig, no Shale, no roc-ast, no second clone: `zig build` fetches webbox itself.

### angry-gopher (`box/roc-cleanup`): the chat's actual Zig host

| piece | lines |
|---|---|
| `chat_router.zig` (the `Call` vtable: 42 hosted functions) | 1,297 |
| `chat.zig` and the `chat_*` files, `presence`, `search_index`, `search_tokens` | 5,841 |

The census measures the chat's live Zig at 28,698 tokens, against 35,613 Roc parse nodes. Routes split 49 to Roc and 1 to Zig.

**The real work is the coupling to the rest of angry-gopher.** The census lists 44 calls from outside the chat into it:
- login;
- settings (`presence.markSeen`, the page chrome);
- the admin pages;
- `app_start` (building the search index, backfilling counts);
- `roots.zig`.

Inside the router, identity comes from angry-gopher's `users.zig`. That file, along with `login.zig` and `uid_cookie.zig`, is tangled up with games code. So the standalone login has to be written new (ROC-CHAT.md's item I3); it can't be lifted out.

### Toolchain

- **Stock Zig is enough on Linux, as measured:**
  - roc-webbox `zig build test` under stock 0.17.0 in a fresh cache passed 17/17 steps, including all the chat seam tests;
  - zig-webbox `zig build test` passed 246/246.

  Our patches fix debug rows, an arena overshoot (6x memory on `/raw`) and a directory-walk loop: they affect quality and memory, not whether the chat builds. angry-gopher's server wasn't built with stock Zig, because it needs generated front-end assets.
- **Roc** is pinned at nightly-2026-10-09-258ab27, which `get_roc.sh` downloads. It's mirrored at showell/roc-apps `toolchain-2026-10-27`.
- **No repo has a LICENSE:** not roc-webbox, zig-webbox, angry-gopher, shale or roc-apps. A repo meant to be forked needs one.

## 2. Layout: (A) a dedicated roc-chat, or (B) chat and TODO together in roc-webbox

The hard work is the same under both: moving the host out of angry-gopher, the identity seam, the Linux main, and the JS client.

| | (A) roc-chat split out | (B) roc-webbox keeps both |
|---|---|---|
| What a forker sees | Only the chat. | The chat plus TODO, `demo/`, `zig build metal`, old probes and the twin harness, under a README that opens with "a Roc platform and a TODO list". |
| Shared glue | roc-chat takes its own copy of the ~500-line runtime glue; TODO keeps its own. | One copy. |
| Drift of that glue | Matters only when TODO and the chat share a binary (through `roc_hooks`); none does today, and mismatched Roc pins already fail at configure. If one ever does, add a byte-identity check like zig-metal-unikernel's `src/pinned/`. | None. |
| Repo name | Matches the task. | "roc-webbox" tells a chat forker nothing. |

**Lean: (A), done last.** Do every move with roc-webbox as the home, where the gates already run, then split with history in one mechanical step. roc-webbox then goes back to being the small "Roc on webbox" example (TODO).

## 3. The options for the Zig layer

| | Drift risk, and what catches it | Forker's learning curve | Bare metal | Code involved |
|---|---|---|---|---|
| **1. Vendor a webbox subset** | High: a second copy of ~9k lines; needs a sync gate. | One clone, with ~9k lines of webbox in their tree. | Unaffected, but two webboxes exist. | ~9,400 lines copied, plus a sync tool. |
| **2. Zig package (URL + hash)** | None: no copy exists. `consumers` builds roc-chat against the live tree. | One clone; `zig build` fetches webbox (tested). | Unaffected. | One zon entry. |
| **3. Submodule or subtree** | Submodule: a pin forkers forget to update. Subtree: a copy, the same as option 1. | Submodule commands trip newcomers. | Unaffected. | Same as 1 or 2. |
| **4. Invert: roc-chat is the chat's one home** | Removes the drift that matters most: one copy of the chat's host, consumed by angry-gopher. | One repo holds the whole chat. | `gopher.elf` builds roc-chat's portable module through angry-gopher. | Moves ~9,500 Zig and ~4,800 JS lines out of angry-gopher. |
| **5. A new small std.http host** | High and silent: webbox's rules (the turn, bus mailboxes, store, cookies, SSE resume) would get a second home, and only behaviour tests would notice. | Smaller Zig to read, but different from production. | Two hosts to keep honest. | ~1-2k new lines. |

4 decides where the chat's code lives; 2 decides how it reaches webbox. They're complementary.

**One spike first, on module identity:** angry-gopher names webbox by path. If roc-chat names it by URL, the build has two webbox packages, and `Bus`/`Request` values crossing between them must come from one module. There are two fixes:
- **(a)** angry-gopher rewires roc-chat's `webbox` import to its own, as zig-metal-unikernel's `addAppKernel` already does, with roc-chat's dependency marked lazy. The agent prefers this one.
- **(b)** `zig build --fork=../zig-webbox` (stock 0.17.0), passed by our gates.

## 4. The forker's path

1. Install stock Zig 0.17.0 and Roc (`tools/get_roc.sh`).
2. Clone your fork of roc-chat.
3. `zig build test`: the first run fetches zig-webbox by its pinned hash.
4. `zig build serve`: data in `data/`, accounts and secrets in `auth/`; a first account through a build step or first-run token (I3, not built yet).
5. In production: a Linux box, with Caddy in front for HTTPS and a systemd unit (the README carries both).
6. Change the chat in `chat/*.roc`, the host in `src/`, and webbox with `zig fetch --save` to a new commit.

No Shale, patched Zig, roc-ast, angry-gopher, zig-metal-unikernel or KVM. Our Shale gates stay in the repo, marked optional.

## 5. What moves, in order

1. **Cut seams in angry-gopher** (on `box/roc-cleanup`, so production master is untouched):
   - an `Identity` seam: who is asking, member or agent, the accounts, the welcome flag;
   - a `Roots` seam for the data root;
   - cut or invert the 44 outside calls.
2. **Move the chat's Zig host and JS client into roc-webbox** as a portable `roc_chat` module (no `webbox_linux`, so `gopher.elf` still builds).
3. **Decide the twin and oracle tests' fate.** They need the old Zig as an oracle, and that Zig is mostly gone.
4. **Build the standalone Linux main and minimal identity (I3).** The Roc still never reads `auth_root`.
5. **Pin webbox by URL and hash** (lazy), rewire it in angry-gopher, and add roc-chat to zig-webbox's `consumers`.
6. **Split roc-chat out with history**, and re-judge `gopher.elf` on KVM before a release.
7. **Forker docs:** README, Caddy and systemd examples, a LICENSE, and the style guide.

## 6. Risks

- **Module identity across URL and path** (§3): spike it before step 5.
- **Roc nightly churn:** forkers sit on a pinned nightly, and moving it is a coordinated change across every Roc consumer.
- **Hosted symbols are weak:** a missing export jumps to address 0. The glue test must travel with the seam.
- **Stock Zig's arena overshoot:** forkers will see higher peak memory on `/raw`.
- **Our quirks travel with the code:** the agent rule, the pinned channels, legacy cookie moves, `__Host-gopher_auth`. Each becomes configuration or is dropped.
- **Search (~7k tokens), uploads and docs are large features** that a forker's first deployment may not want.
